# CO-011: Agent identity and credential lifecycle

**Implementation status:** partial. Provider-neutral scoped agent credentials are implemented and tested; the agent principal registry, route integration, delegation policy and production scope registry are not implemented.

## Implemented backend foundation

- Issues opaque `fg_agent_` credentials backed by 256-bit cryptographic randomness. The database stores only a SHA-256 hash and a short display prefix; the raw token is returned once to the trusted issuing caller.
- Binds every credential to an explicit `agentId`, `tenantId`, allowlisted scopes, creation time and expiry.
- Requires the caller to provide the expected tenant when authenticating. A credential for another tenant is rejected.
- Requires explicit allowed scopes and TTL policy at service construction; no default agent privileges are granted.
- Tracks last-used time and refuses authentication when a credential is expired, revoked or concurrently revoked during the last-used update.
- Supports individual revocation, revoke-all for an agent+tenant, and atomic credential rotation that revokes the old credential and inserts the replacement in one transaction.
- Adds SQLite and PostgreSQL stores and identity migration v6.
- The existing `Actor.kind = 'agent'` event metadata remains audit attribution only; it is not treated as proof of an authenticated agent principal.

## Deliberate non-implementation boundary

- No agent principal registry or creation workflow is wired. A trusted backend caller must supply agent and tenant identifiers.
- No HTTP/API-key authentication route is mounted and no protected application route consumes `AgentPrincipal` yet.
- No delegation, impersonation, service-to-service audience, workload identity, credential approval workflow or agent-to-user ownership relationship is inferred.
- No global scope registry or default scopes are selected; issuance requires an explicit allowlist and explicit scopes.
- No agent audit event integration is wired yet.
- PostgreSQL adapter/migration are implemented but have not been exercised against a live PostgreSQL service.
