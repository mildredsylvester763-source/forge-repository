# AI-080: Approval gates

## Behaviour

- A plan is gated when any trigger fires: the risk level is always-risk (high by default), the tool class is sensitive (write, exec and network by default), or the cost exceeds the maximum auto-approved cost (1000 by default).
- Triggers are reported deterministically in the order risk, tool, cost, for example risk:high, tool:write, cost:5000>1000.
- Custom policies can tighten or loosen any of the three knobs; malformed policies are refused as approval-policy-invalid.
- Resolving a gate is approve or reject, normalised to lowercase. A rejection requires a stated, non-blank reason; the stored reason is trimmed.

## Where it lives

src/modules/task-runtime/engine/approval-gates.ts (pure), reached through POST /v1/tasks/approval/plan, POST /v1/tasks/approval/resolve, GET /v1/tasks/approval/risks and GET /v1/tasks/approval/tool-classes.

## Limits, stated plainly

Planning is stateless: it answers whether approval is needed, it does not hold a gate open. Gate lifecycle persistence lives in the task history journal (AI-082).
