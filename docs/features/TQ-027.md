# TQ-027: Creative tool operation

## Behaviour

- Three editors with exact operation vocabularies: manhwa (draw, paint, layer-add, layer-merge, layer-hide, undo, redo), three-d (object-add, object-move, object-rotate, camera-orbit, undo, redo) and music (note-place, note-drag, clip-trim, instrument-select, undo, redo).
- Operations track per editor state: layers, objects, notes, undoDepth and redoDepth. Any new edit clears the redo stack; undo and redo move depths in pairs.
- Limits are hard: 50 layers with a floor of 1, 200 objects, 500 notes, all refused by name (creative-layer-limit, creative-layer-floor, creative-object-limit, creative-note-limit).
- Garbage state resets to the initial state instead of crashing; unknown editors and operations are refused by name.

## Where it lives

src/modules/live-testing/engine/creative-tool-operation.ts (pure), GET /v1/live-testing/creative for the catalog and POST /v1/live-testing/sessions/creative for each edit (per editor state, per session).

## Limits, stated plainly

The state machine counts edits; it does not render strokes or audio. Undo restores counters, not artwork.
