# AI-070: Search cache with TTL bands and a token bucket

## Behaviour

- Cache keys normalize deterministically: trimmed, lowercased, inner whitespace collapsed. Entries carry a lane, a payload, a TTL and a hit count, and are owned per user.
- Age bands: fresh below half the TTL, stale from half the TTL until the TTL, expired past it. TTL must be an integer in 1..86400 seconds. Re-storing an existing key upserts and resets the hit count.
- The token bucket caps at capacity, refills per minute and spends one token per allowed call. Elapsed minutes must sit in 0..1440.
- Refusals are named: cache-key-missing, cache-ttl-invalid, cache-entry-not-found, cache-entry-expired, bucket-elapsed-invalid.

## Where it lives

src/modules/search-integrity/engine/search-cache.ts (pure), reached through POST /v1/search-integrity/cache, POST /v1/search-integrity/cache/get and POST /v1/search-integrity/rate/check.

## Limits, stated plainly

This is an application cache per user, not a CDN and not a shared vector store. The rate route honors elapsed minutes only; bucket tuning happens inside the engine, not through the API.
