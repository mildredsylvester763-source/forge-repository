# AI-002: Consent registry

## Behaviour

- Consent is granular per workspace, user and dataType, and the default is DENY: an unknown triple is never granted.
- A grant is idempotent while it is live: a second grant for an active triple returns the existing record, whatever the purpose.
- Revocation is immediate and audited. A revoke without an active, unexpired grant is refused with consent-no-active-grant naming the triple.
- Expiry is inclusive: a check at exactly expiresAt reads expired. An expired grant cannot be revoked, only superseded by a fresh grant, and a superseded grant can never resurface after the newer one is revoked.
- Every state change lands in the ledger, grant and revoke alike. Reads and checks never mutate anything.
- Expiry at or before now is refused with consent-expiry-in-past, and refusals leave the state untouched.

## Where it lives

src/modules/training-data/engine/consent-engine.ts (pure), reached through POST /v1/training-data/consent/grant, POST /v1/training-data/consent/revoke, POST /v1/training-data/consent/check, POST /v1/training-data/consent/ledger and POST /v1/training-data/consent/list.

## Limits, stated plainly

This is a registry of consent records, not a legal counsel: the purpose is stored and audited, but nothing compares it against what the data is actually used for. Quality of a source is never a consent question.
