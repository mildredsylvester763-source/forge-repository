# AI-088 - Clarifying questions only when intent is truly ambiguous

Catalog row (Part 01 With Plans): "Clarifying questions only when intent is truly ambiguous" - Plan from: Free, Engine: General, no pass needed.

## What it is
The interrogate-only-when-needed law. Every question must anchor to a NAMED ambiguity signal (missing-input, conflicting-constraint, multiple-interpretations, unknown-scope); a clear intent is never interrogated, and questions without a named ambiguity are refused outright.

## Engine
`src/modules/ai-training/engine/clarifying-questions-engine.ts` - pure.
- `decideClarification({ intent, signals, questions })` - a non-empty intent; zero or more ambiguity signals (unique ids, named kinds, descriptions); zero or more questions, each anchoring to at least one known signal id. `needed` is true only when at least one signal is named; when ambiguous but no questions are drafted the decision carries the issue `no-questions-drafted`. The decision carries a `cq_` fingerprint and never mutates the caller input.

Refusals: `clarify-no-intent`, `clarify-signals-not-a-list`, `clarify-signal-invalid:<i>`, `clarify-signal-no-id:<i>`, `clarify-signal-duplicate:<id>`, `clarify-kind-invalid:<kind>`, `clarify-signal-no-description:<id>`, `clarify-questions-not-a-list`, `clarify-question-invalid:<i>`, `clarify-question-no-text:<i>`, `clarify-question-unanchored:<i>`, `clarify-anchor-invalid:<i>`, `clarify-anchor-unknown:<id>`, `clarify-no-ambiguity`.

## Routes (POST, session required, gate: free)
- `/v1/ai-training/clarify/decide` - 200, the decision (needed, reason, questions, issues, fingerprint) and its createdAt

## Honest state
Decisions live in an in-memory session Map (the streaming-sessions precedent): a restart clears them, nothing is persisted yet. The engine judges only what the caller submits - it never invents ambiguity to justify questions.
