# TQ-030: Safe mode

## Behaviour

- Safe mode is forced on for production environments, whatever the request says; test environments honor the requested setting and unknown environments stay safe.
- In safe mode, recorded steps are refused by name when they are destructive (delete, wipe, purge and friends), payment related (pay, purchase, checkout and friends), real message sends (send-message, post, publish and friends) or type real looking email addresses.
- Refusals are named: safe-mode-blocks-destructive:A, safe-mode-blocks-payment:A, safe-mode-blocks-real-message:A, safe-mode-blocks-real-address:A, safe-mode-action-missing.
- Out of safe mode the same steps pass; the switch is a property of the session, not of the caller.

## Where it lives

src/modules/live-testing/engine/safe-mode.ts (pure), applied when a session is created (the environment decides the forced flag) and on every recorded step while safe mode is on.

## Limits, stated plainly

Blocking is name and pattern based: it refuses obviously dangerous verbs and real looking addresses, it does not prove a payload is harmless.
