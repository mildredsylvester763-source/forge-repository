# CO-005: Multi-factor authentication

**Implementation status:** partial TOTP cryptographic primitives implemented. Enrollment, persistence, account enforcement and recovery are not implemented.

## Implemented primitive layer

- Generates cryptographically random TOTP secrets with a bounded size of 20–64 bytes.
- Encodes and strictly decodes canonical Base32 secrets.
- Generates RFC 6238 time-based one-time passwords using explicitly supplied SHA-1, SHA-256 or SHA-512 algorithm, 6/8 digits and 15–120 second period.
- Verifies a candidate with an explicitly supplied time-step window (0–2 steps) using constant-time comparison.
- Returns the matched moving factor and drift so a future persistence layer can enforce one-time use with an atomic compare-and-swap.
- Produces an `otpauth://totp` provisioning URI from explicit issuer, account label, secret and options.
- Tests include RFC 6238 published SHA-1 vectors, canonical Base32 round trips, window behavior, malformed inputs and URI parameters.

## Deliberate non-implementation boundary

- No MFA enrollment, confirmation, disable, step-up challenge or login enforcement route exists.
- No secret persistence or encryption exists. Do not persist TOTP seeds in plaintext or log provisioning URIs; the URI contains the secret.
- No replay-prevention store is wired. A successful code must not be accepted again for the same moving factor; the future storage operation must atomically persist the greatest accepted step.
- No backup/recovery codes, lost-device recovery, rate-limit policy, administrator reset, or email/SMS delivery exists.
- Generating or verifying a TOTP code alone does not establish MFA for an account.

## External and owner decisions still required

- Exact owner-supplied Part 01 CO-005 acceptance text and whether MFA is optional, mandatory, policy-scoped or step-up-only.
- Product/security approval of supported algorithms, code length, period, clock-drift window, enrollment confirmation and replay policy.
- KMS/key-custody owner and approved encryption/key-rotation/recovery boundary for stored TOTP secrets.
- Account recovery and backup-code policy; email/SMS transport providers and credentials are activation-time dependencies if the accepted policy uses them.
- Support/security staff authority for assisted recovery and factor resets.

**Approval state: NOT GRANTED.** The crypto primitives are not a complete or production-enabled MFA feature.
