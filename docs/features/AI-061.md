# AI-061: Domain allow and deny lists per workspace

## Behaviour

- Every user and workspace carries an allow list and a deny list, 200 entries each, stored and edited through the domain-rules routes.
- Deny always wins over allow. An empty allow list means everything is allowed, subject to deny.
- A bare domain matches the host and any subdomain; a wildcard pattern matches subdomains only.
- Rule lists are validated entry by entry in order: rules-not-a-list, rules-not-a-string, rules-empty-domain, rules-invalid-domain, rules-duplicate-domain, rules-too-many. Allow and deny may not overlap (rules-allow-deny-overlap).
- Evaluation refusals are named: domain-empty-host, domain-invalid-host, domain-denied, domain-not-allowlisted.

## Where it lives

src/modules/web-search/engine/domain-policy.ts (pure), reached through GET and POST /v1/web-search/domain-rules and POST /v1/web-search/domain-rules/get; search and page fetch consult the rules before ranking or storing anything.

## Limits, stated plainly

Matching is hostname text only: no IP resolution, no port or path rules, no category feeds. Denying example.com does not block lookalikes such as examp1e.com or example.com.evil.net.
