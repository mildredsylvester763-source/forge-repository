# CO-096: Verified backups (repository-derived descriptor; original catalogue title unavailable)

**Classification: PARTIAL.** SQLite snapshots are created and verified; automated PostgreSQL/off-site backup and restore are not implemented.

## Existing implementation

- `src/kernel/backup.ts` creates consistent SQLite snapshots with `VACUUM INTO`, writes a SHA-256 sidecar, verifies the checksum, runs SQLite integrity checking and verifies the stored event chain.
- `test/backup.test.ts` covers checksum presence, format and mismatch behavior.
- Configuration permits a local SQLite backup directory and bounded interval/retention settings. Production PostgreSQL backup is explicitly not automated.

## Safe hardening completed in this continuation

- Replaced whole-file `readFileSync` hashing with a 1 MiB streaming read loop, bounding checksum memory independent of backup size.
- `pruneBackups()` now rejects zero, negative, fractional and unsafe retention counts before it can delete files.
- `startBackupSchedule()` now validates interval and retention before running its immediate first backup, preventing invalid zero-interval scheduling or unsafe pruning.
- Added repository regressions for multi-megabyte snapshot verification, invalid retention preserving existing files, and invalid schedule rejection before backup creation.
