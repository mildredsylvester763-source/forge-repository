# AI-041: Streaming responses with cancel and resume

## Behaviour

- Chunk indices are strict: a gap is refused by name (stream-chunk-out-of-order) so a hole can never silently corrupt an answer. Streams have a chunk cap, refused loudly (stream-chunk-cap).
- Cancel is idempotent and terminal; complete refuses after cancel and double-completes are refused. Any event on a non-open stream is refused naming the status.
- Resume: the client names the last chunk index it saw and the stream replays exactly the suffix after it. A client ahead of the stream is refused (resume-ahead-of-stream) - it can never invent unseen content.

## Where it lives

src/modules/ai-training/engine/model-operations-engine.ts (pure), reached through POST /v1/ai-training/ops/streams/start, /v1/ai-training/ops/streams/event and /v1/ai-training/ops/streams/resume.

## Limits, stated plainly

- Streams live in memory per user. They are not durable across a restart; the client resumes within a session, not after one.
