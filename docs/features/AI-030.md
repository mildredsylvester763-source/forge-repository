# AI-030: Per-agent scorecards

## Behaviour

- Events record agent, outcome success or failure, and optional reverted and approved flags; record time is permissive, but a scorecard build refuses bad stored events by name (scorecard-event-invalid-outcome).
- Rates are honest: success and revert per total events, approval per decided events only, so undecided events never dilute an approval rate.
- Agents below the events floor are still tallied but named in insufficient; refusals named: scorecard-no-events, scorecard-invalid-min-events, scorecard-event-no-agent.

## Where it lives

src/modules/ai-training/engine/product-experiment-engine.ts (pure), reached through POST /v1/ai-training/agents/events and POST /v1/ai-training/agents/scorecards.

## Limits, stated plainly

Agent identity is a string; the engine cannot tell two deployments of the same agent apart. Rates describe the past, they carry no confidence interval.
