# AI-009: Preference signals

## Behaviour

- Signals are explicit only: like, dislike, skip. Nothing is inferred, ranked or deduced from behaviour; an unknown signal is refused by name.
- Storage is consent-gated: the subject must hold a live consent grant (workspace default, dataType preference, AI-002) or the store is refused with preference-consent-required.
- One signal per (user, item, signal) identity. Re-submitting the same signal is idempotent: the existing record returns with duplicate true and nothing is appended.
- Contradictory signals on one item coexist as separate records: a like and a dislike for the same item are both stored, never merged.
- Reads never mutate: the list filters by subject and pages. Revoking consent closes the gate for new signals, but stored records still read back.

## Where it lives

src/modules/training-data/engine/preference-engine.ts (pure), reached through POST /v1/training-data/preference/store and POST /v1/training-data/preference/list.

## Limits, stated plainly

Consent is checked per subject name against the owner's registry, not proven per subject. Revoking consent does not delete stored signals; it only stops new ones. The store is append-only, so a stored signal is never edited, only joined by a later explicit signal.
