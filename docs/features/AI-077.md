# AI-077: Tool registry and permissions

## Behaviour

- Tools are registered with a class (read, write, exec, network) from a fixed catalog of eight tools.
- Agents get per-tool allowlists that deny by default: a pair outside the allowlist is a named refusal, never a silent skip.
- Every plan action maps to exactly one required tool, so a plan can be expanded into its tool needs.
- Malformed input is refused by name: tool-agent-missing, tool-agent-unknown:x, tool-name-missing, tool-unknown:x, tool-denied:agent:tool, tool-plan-empty, tool-action-unknown:x.

## Where it lives

src/modules/orchestrator/engine/tool-registry.ts (pure), reached through POST /v1/orchestrator/tools/check, POST /v1/orchestrator/tools/plan, GET /v1/orchestrator/tools and GET /v1/orchestrator/tool-classes.

## Limits, stated plainly

Permissions are checked before execution, they are not a sandbox: an allowed tool still runs inside the execution sandbox (AI-078).
