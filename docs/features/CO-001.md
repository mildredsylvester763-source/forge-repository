# CO-001: Email and password sign-in with breached-password checks

## Behaviour

- **Register**: normalises the email, applies the password rules, checks the breach services, hashes, stores, emits an event.
- **Sign in**: throttles, verifies in constant-ish time, upgrades the hash if parameters or pepper are outdated, re-checks the password against breaches, issues a session, emits an event.
- **Sign out / me**: revoke and read the current session.

## Password rules (NIST 800-63B)

12 to 128 characters, any characters allowed (spaces and Unicode included), no forced symbols or digits. Rejected: control characters, one repeated character, passwords containing the account email, anything in a known breach.

## Breach checking

Two layers: an instant local blocklist, then the Have I Been Pwned range API with padding.

If the breach service is unreachable:
- `fail-closed` (default): registration returns 503. Safer.
- `fail-open`: registration proceeds and a `breach_check_skipped` event is recorded.

Sign-in never fails because of the breach service. If the check cannot run, sign-in proceeds.

## Limits, stated plainly

In-memory storage. No email verification. No password-change endpoint yet, so `passwordChangeRequired` is a flag the client can show. Session tokens are cookie-only (browser). Tokens for the Android and desktop clients arrive with CO-007 and CO-009.
