# AI-079: Step validation

## Behaviour

- Validates the output of one completed step against an ordered list of checks: exit-code, field, max-length, contains, equals.
- Failed checks are verdicts, not errors: the answer is ok false plus named failure details in check order (exit:1, field-missing:title, max-length:notes:5>4, contains:final, equals-mismatch).
- Malformed requests are refused by name: stepv-step-id-missing, stepv-step-id-too-long, stepv-checks-missing, stepv-checks-empty, stepv-checks-limit:51, stepv-check-missing:n, stepv-check-type-unknown:type and friends. At most 50 checks per step; step ids are capped at 100 characters.
- contains and equals compare against stable, key-sorted serialization, so key order never changes a verdict.

## Where it lives

src/modules/task-runtime/engine/step-validation.ts (pure, zero imports), reached through POST /v1/tasks/step/validate and GET /v1/tasks/step/checks.

## Limits, stated plainly

Validation is per step output and stateless: the route validates, it never stores. No check crosses a step boundary.
