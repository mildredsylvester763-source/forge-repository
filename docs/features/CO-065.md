# CO-065: Atomic event writes (repository-derived descriptor; original catalogue title unavailable)

**Classification: PARTIAL.** Selected identity state changes and event appends are atomic; durable subscriber delivery is not implemented.

## Evidence
- `src/modules/identity/unit-of-work.ts` defines the identity unit-of-work contract.
- `src/modules/identity/postgres-stores.ts` uses one transaction for selected user/session mutations and `PostgresEventStore.appendIn()`, then notifies after commit.
- SQLite identity storage has a corresponding transactional unit-of-work path.
- `test/co-065-postgres-uow.test.ts` covers rollback on event failure and successful identity transitions.
- Mistral's `EventDispatcher` is explicitly best-effort/in-process; there is no durable queue or retry.

## Remaining boundary
A process can fail after the database commit but before in-process notification. There is no durable subscriber outbox, consumer offset, retry/backoff, dead-letter, retention or replay contract. Those semantics require owner decision; they must not be guessed. Exact original Part 01 wording is also unavailable.

**Owner decision:** delivery guarantee, outbox ownership, per-consumer offsets, retry/backoff, dead-letter behavior, retention and replay/recovery. No external credential is inherently required for an internally hosted outbox.
