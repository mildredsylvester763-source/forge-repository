# CO-002: Passkey / WebAuthn protocol core

**Status:** Partial protocol core implemented and focused-workflow verified. Exact original Part 01 acceptance wording is unavailable; no complete passkey account lifecycle or production authenticator integration is claimed.

## Implemented protocol primitives

- Generates cryptographically random 32-byte challenges and creates discoverable registration/authentication option objects with required user verification.
- Validates exact configured HTTPS origins (HTTP only for localhost development), RP-ID syntax and the RP-ID/origin relationship.
- Parses bounded CBOR and WebAuthn client/authenticator data with byte-size, depth and item-count limits.
- Accepts privacy-preserving `none` attestation only; unsupported attestation formats fail closed.
- Extracts public keys for ES256, Ed25519 and RSA COSE keys.
- Verifies assertions, signatures, credential ID binding, challenge/origin, RP-ID hash, user presence/verification, user handle and authenticator counter rollback.
- Rejects malformed base64url, truncated/trailing CBOR, malformed credentials and unsupported ceremony data.

## Explicit limits

- No durable challenge store, atomic one-time challenge consumption, credential repository, credential-management routes or account-to-credential lifecycle exists yet.
- No end-to-end registration or passkey sign-in endpoint is exposed.
- No production RP ID/origin, domain ownership proof or real authenticator credential has been supplied.
- `none` attestation does not prove authenticator model or hardware provenance.
- Assertion sign-counter persistence and concurrent update handling are not wired because credentials are not yet persisted.

## Verification

Focused regressions cover options, registration parsing, ES256 key extraction, assertion signature verification, challenge/origin/RP binding, counter rollback, user-handle matching, malformed CBOR and origin configuration. The isolated CO typecheck and test workflow passed with these tests included.

## Owner decisions still open

Exact CO-002 acceptance wording, final production RP ID/origins, supported authenticator policy, attestation expectations, resident/discoverable credential policy, backup eligibility semantics and credential lifecycle remain to be reconciled with the original catalogue. Production origins are activation-time configuration, not hard-coded constants. No live relying-party domain or credentials were fabricated. No owner acceptance is implied by implementation.
