# AI-065: Duplicate-aware result reranking

## Behaviour

- Candidates are deduplicated by canonical key: trimmed, lowercased, first occurrence wins; duplicates are counted and dropped.
- Remaining results are chosen greedily by maximal marginal relevance: margin is score minus lambda times the Jaccard similarity of title plus body token sets against every already-picked result.
- Lambda defaults to 0.5 and must sit in 0..1; depth defaults to 10 and must be an integer in 1..50. Ties within 1e-12 break by canonical key ascending.
- Refusals are named: rerank-candidates-empty, rerank-lambda-invalid, rerank-depth-invalid, rerank-key-missing, rerank-score-invalid.

## Where it lives

src/modules/workspace-retrieval/engine/result-rerank.ts (pure), reached through POST /v1/workspace-retrieval/rerank.

## Limits, stated plainly

Similarity is token overlap only; there is no cross-encoder and no semantic model. Scores arrive precomputed, so garbage in still ranks confidently.
