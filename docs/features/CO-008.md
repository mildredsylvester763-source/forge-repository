# CO-008: Email verification and password recovery

**Implementation status:** partial, provider-neutral one-time action-token engine and persistent token stores are implemented. Email delivery, account-state changes, password reset/session handling and HTTP routes are not implemented.

## Implemented backend foundation

- Issues cryptographically random 256-bit tokens for `email_verification` and `password_recovery` purposes.
- Stores only the SHA-256 token hash. The raw token is returned only to the internal caller so a future delivery adapter can send it; it is not stored or logged by this service.
- Binds each token to a user ID, purpose, user version, creation time and explicit expiry.
- Allows only one outstanding token per user and purpose; issuing a replacement invalidates the previous token for that purpose.
- Rejects malformed, expired, wrong-purpose and stale-user-version tokens.
- Consumes valid tokens atomically and once-only. Concurrent consumers cannot both succeed.
- Adds SQLite and PostgreSQL stores and identity migration v5. The PostgreSQL adapter uses row locking around replacement and atomic token consumption.
- Requires explicit configured TTLs for each purpose and bounds them between one minute and 24 hours; no product-specific expiry policy is silently selected.

## Deliberate non-implementation boundary

- No email/SMS delivery provider is selected or connected. The service is transport-neutral; provider credentials and sender-domain verification are activation inputs.
- No HTTP request/consume routes are mounted.
- Consuming an email-verification token does not yet update a user verification field or enforce verified-email sign-in policy.
- Consuming a password-recovery token does not yet update the password hash, revoke sessions or emit the complete recovery audit event. Those operations must be integrated atomically through the identity unit of work.
- No account-enumeration response contract, identity-proofing/recovery policy, password-reset UX, support-assisted recovery or backup recovery channel is enabled.
- The PostgreSQL adapter/migration has not been tested against a live PostgreSQL service; focused tests exercise SQLite.
