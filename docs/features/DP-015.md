# DP-015 — Deployment dependency graph so services ship in the right order

**Catalog source:** *Forge Feature — Catalog Part 02 With Plans.pdf*, page 3.  
**Plan from:** Pro.  
**Engine:** General.  
**Sold as:** Base plan from the Plan from column; no engine pass.

## Current implementation

The Pro-gated `POST /v1/deployments/dependency-graph/plan` endpoint accepts a caller-supplied service dependency graph and returns a deterministic dependency-first order plus parallelizable release waves. The planner rejects duplicate service IDs, duplicate/self/unknown dependencies, malformed identifiers, oversized graphs and cycles. A cycle response includes a concrete cycle path; invalid graphs never receive a partial order.

## Verification

See `test/deployment-dependency-graph.test.ts` for deterministic ordering, input-order independence, cycle and input validation, authentication, Pro entitlement enforcement and route-boundary validation.

## Explicit scope limit

**DP-015 is partially implemented, not end-to-end deployment.** This backend currently has no deployment provider, persisted service registry, repository-to-service discovery, or release executor. The endpoint plans only the graph supplied in the request and does not claim to ship services. Provider-backed release integration remains blocked by the deployment-target authorization recorded in `docs/part02-audit-ledger.md`.
