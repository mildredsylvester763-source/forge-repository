# AI-033: Model registry: versions, lineage, datasets, evals, owners

## Behaviour

- Versions are sequential per model: the registry assigns the next number, and refuses duplicates (registry-duplicate-version) and gaps (registry-version-gap). A version without owners is refused (registry-no-owners).
- Lineage (dataset, eval suite, run fingerprint) travels with the version. Each record is fingerprinted (modfp_ prefix) over model, version, owners and weights, so the same inputs always give the same fingerprint while each user only ever sees their own versions.
- Listing returns newest first and always tells the whole count.

## Where it lives

src/modules/ai-training/engine/model-registry-engine.ts (pure), reached through POST /v1/ai-training/models/versions and /v1/ai-training/models/versions/list.

## Limits, stated plainly

- Weights are fingerprinted, never stored in the app; the bytes belong in R2. The registry records what was registered, not that the weights are good.
