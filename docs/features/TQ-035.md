# TQ-035: Fuzz testing

## Behaviour

- A fuzz campaign is budgeted (1 to 1000 cases, default 100) and seeded (default 42) so every run is reproducible. Two market modes: grammar and mutation.
- Grammar mode generates from typed fields (string 1..12 lowercase chars, int 0..999, bool, uuid in 8-4-4-4-12 hex): required fields are always present, optional fields are omitted when the PRNG says so. Mutation mode picks a known-good sample per case, then deletes, inserts, duplicates or flips a character at a named position.
- Malformed input is refused by name: fuzz-kind-missing, fuzz-kind-unknown:x, fuzz-budget-invalid:n, fuzz-seed-invalid:n, fuzz-input-missing, fuzz-fields-empty, fuzz-field-name-missing, fuzz-field-type-unknown:x, fuzz-field-duplicate:x, fuzz-samples-empty, fuzz-sample-invalid.

## Where it lives

src/modules/test-generation/engine/fuzz-testing.ts (pure), reached through POST /v1/test-generation/fuzz/run. GET /v1/test-generation/fuzz/kinds and GET /v1/test-generation/fuzz/field-types list the catalogs.

## Limits, stated plainly

The grammar is declared, not inferred from a spec: field types cover the four shapes the market proved dominant, and mutation only perturbs single characters of the samples given to it.
