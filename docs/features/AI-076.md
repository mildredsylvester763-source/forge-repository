# AI-076: Agent selection and handoffs

## Behaviour

- Each step is assigned to the first agent in the roster whose capabilities cover its action (coordinator, researcher, writer, executor, reviewer).
- Handoffs are recorded at the step boundary where ownership changes.
- The classic multi-agent failure, the infinite ping-pong loop, is refused with named bounce detection.
- Malformed input is refused by name: handoff-action-missing, handoff-steps-empty, handoff-roster-empty, handoff-agent-unknown:x, handoff-agent-duplicate:x, handoff-no-capable-agent:x, handoff-bounce-detected:a->b->a.

## Where it lives

src/modules/orchestrator/engine/agent-selection.ts (pure), reached through POST /v1/orchestrator/handoffs and GET /v1/orchestrator/agents.

## Limits, stated plainly

Selection is capability-based only; it does not model load, latency or cost. Bounce detection is one step deep by design.
