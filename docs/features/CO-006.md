# CO-006: Session manager

**Implementation status:** implemented provisionally in this branch; exact Part 01 acceptance wording has not been recovered, so catalogue acceptance is not yet verified.

## Authenticated API

- `GET /v1/auth/sessions` lists active sessions for the account bound to the authenticated server-side session.
- `POST /v1/auth/sessions/revoke` accepts exactly one `sessionId` and revokes only a session owned by the authenticated account.
- The response identifies the current session. Revoking the current session expires its cookie in the same response; revoking another device does not disturb the caller's current session.
- Unknown and foreign-account session IDs produce the same not-found response. A session ID is not a bearer credential.
- A missing, expired, idle-expired, revoked or disabled-account session cannot list or revoke sessions.

## Security and audit properties

- Session bearer tokens remain cookie-only and are never stored or returned by the manager. Public records expose the SHA-256 session reference, timestamps, IP address, user agent and current-session flag.
- Ownership is checked server-side before a revoke; client-supplied account identifiers are not accepted.
- Revocation is committed through the identity unit of work. SQLite and PostgreSQL implementations persist the revocation and `identity.session.revoked` event atomically; in-memory storage follows the same contract for tests.
- The audit event contains a shortened session reference and the operation reason, never the bearer token.
- The default sign-out reason remains `user_sign_out`; explicit manager revocation uses `session_manager`.

## Routes

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/v1/auth/sessions` | List the caller's active sessions |
| POST | `/v1/auth/sessions/revoke` | Revoke one caller-owned session |

## Deliberate limits

- This implementation does not infer device naming, location enrichment, bulk sign-out, administrator session control, or session UX requirements that are not present in the available repository specification.
- Session metadata is visible only to the authenticated owner. IP and user-agent are operational metadata and should be handled as personal data.
- Exact Part 01 wording is still required before the feature can be accepted as matching the owner's catalogue. No positive owner approval of this provisional API shape is implied by silence.
- CO-006 does not resolve the separate native-client token contracts (CO-007/CO-009), account recovery (CO-008), or MFA (CO-005).
