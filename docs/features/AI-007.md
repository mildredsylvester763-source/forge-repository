# AI-007: Synthetic data manifests

## Behaviour

- Every synthetic record declares itself synthetic and carries full generator provenance: model, version and seed are all mandatory. A record that reaches the registry under any other provenance is refused as unattributed.
- The content hash is not supplied by the caller. It is derived from the generator identity and the ordered base list, so re-registering the same manifest is an idempotent duplicate rather than a new record. Base order is identity: reversing it produces a different record.
- Every base must already exist, in the synthetic registry or in the data lake (AI-001). A record listing its own future id is refused as synthetic-self-base.
- Depth is derived: a baseless record sits at 0, a derived one at max base depth + 1.
- The chain walker returns the full provenance chain root-first, across both registries, sorted by depth then id.

## Where it lives

src/modules/training-data/engine/synthetic-engine.ts (pure), reached through POST /v1/training-data/synthetic/register, POST /v1/training-data/synthetic/chain and POST /v1/training-data/synthetic/list.

## Limits, stated plainly

The manifest proves what generated the data and from what, not that the output is any good. Quality is judged downstream in the lake, where synthetic records count against the ai cap like any other ai-provenance record.
