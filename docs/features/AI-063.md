# AI-063: Workspace content retrieval

## Behaviour

- Content items arrive from five named sources (code, docs, issues, chats, assets) and are stored per user with title, body and links to pre-existing items.
- Search scores each item per query term: a title hit is worth 3, a body hit is worth 1. Hits sort by score descending, then id ascending.
- Optional source filters are trimmed and lowercased. Refusals are named: retrieval-query-missing, retrieval-sources-not-array, retrieval-sources-empty, retrieval-source-unknown.
- Recording refusals: items-empty, items-count-invalid (over 200), item-source-unknown, item-title-missing, item-title-too-long, item-body-missing, item-body-too-long, item-links-not-array, item-links-too-many, item-link-missing, item-link-unknown. Links resolve against pre-existing items only.

## Where it lives

src/modules/workspace-retrieval/engine/workspace-retrieval.ts (pure), reached through POST /v1/workspace-retrieval/items, POST /v1/workspace-retrieval/items/list and POST /v1/workspace-retrieval/workspace/search.

## Limits, stated plainly

Matching is plain substring counting: no stemming, no phrases, no proximity. The service scans up to 1000 stored items per query, so very large workspaces are not fully searched.
