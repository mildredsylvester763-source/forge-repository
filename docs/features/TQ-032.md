# TQ-032: Integration test generation

## Behaviour

- An integration suite is planned from a service dependency graph: one covering case per unique edge (deduped, first-seen order), a DFS cycle check that names the cycle path, and a Kahn topological order for safe execution sequencing.
- Services are strings or objects with a name; dependencies are pairs; edges referencing unknown services are refused by name.
- Malformed input is refused by name: integration-services-empty, integration-service-name-missing, integration-service-name-too-long, integration-service-duplicate:x, integration-dependencies-empty, integration-dependency-name-missing, integration-node-unknown:x, integration-cycle-detected:a->b->a.

## Where it lives

src/modules/test-generation/engine/integration-graph.ts (pure), reached through POST /v1/test-generation/integration/plan.

## Limits, stated plainly

The graph is declared by the caller, not discovered: a missing edge means no case, not a wrong suite. Cycles are a planning failure, never an ordering guess.
