# TQ-038: Snapshot and golden-file testing

## Behaviour

- A snapshot is a human-readable canonical serialization (sorted keys, two-space indent, one array element per line) with an FNV-1a 32-bit checksum, recorded once and verified on every later run.
- Three modes: write (record, refuses if one exists), verify (compare, reports checksums and the first differing line) and update (explicit re-record, refuses if none exists). Names match a lowercase kebab pattern.
- Malformed input is refused by name: snapshot-name-missing, snapshot-name-invalid:x, snapshot-mode-missing, snapshot-mode-unknown:x, snapshot-value-missing, snapshot-exists:x, snapshot-missing:x, snapshot-stored-invalid, snapshot-mismatch:x.

## Where it lives

src/modules/test-quality/engine/snapshot-testing.ts (pure), reached through POST /v1/test-quality/golden/write, /v1/test-quality/golden/verify, /v1/test-quality/golden/update and GET /v1/test-quality/golden/list. Goldens persist per user in test_quality_goldens. GET /v1/test-quality/snapshot/modes lists the modes.

## Limits, stated plainly

Snapshots pin what was recorded, not what is correct. An explicit update is always required to change a golden; nothing updates itself.
