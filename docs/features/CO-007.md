# CO-007: Native-client session tokens

**Implementation status:** implemented against the explicit repository-documented native bearer-session contract; catalogue acceptance is unverified because the exact original Part 01 wording is unavailable.

## Native sign-in and session use

- `POST /v1/auth/native/sign-in` accepts the existing email/password sign-in contract and returns an opaque 256-bit session bearer token, its expiry timestamp and the public user record.
- It does not set a browser cookie.
- Native clients send `Authorization: Bearer <token>` to protected FORGE routes. The bearer value is accepted by the identity route, session manager and protected module routes.
- `POST /v1/auth/native/sign-out` revokes the server-managed session. Session manager listing/revocation also accepts bearer credentials.
- If an Authorization header is present but malformed, authentication fails closed. It does not fall back to a valid browser cookie.
- The server stores only the SHA-256 token reference, not the bearer token itself.

## Lifecycle boundary

The native token is the same opaque server-side session credential used by the browser session system. It inherits absolute expiry, idle expiry, per-account active-session limit and server-side revocation. This is not a JWT, OAuth access token, refresh token or self-contained offline credential.

No refresh-token issuance, refresh-token rotation, device enrollment attestation, offline grace period or native app attestation is implemented. After expiry or revocation, the client must authenticate again. Tokens must be sent only over HTTPS and stored in the platform's secure credential storage; they must not be placed in URLs, logs or analytics.

## Authorization integration

Bearer credentials are recognized by the protected route modules without changing resource ownership checks. This change does not grant cross-account resource access and does not establish tenant membership, project roles or the CO-029–CO-044 policy model.

## Verification

The focused CO workflow includes native sign-in, bearer access to `/v1/auth/me`, session listing/revocation, bearer sign-out, no-cookie behavior and malformed-header no-fallback tests.
