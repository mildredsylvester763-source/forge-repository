# CO-012: Sign-in anomaly detection

**Implementation status:** observe-only signal detection implemented provisionally. Exact Part 01 acceptance wording remains unavailable, so catalogue acceptance is not verified.

## Current behavior

After a successful password verification and before a new session is created, the identity service compares the current request's IP address and user-agent against the authenticated account's currently active sessions.

It may report these value-free signals:

- `new_active_session_ip`
- `new_active_session_user_agent`
- `new_active_session_device`

The assessment also records whether an active-session baseline existed or whether client metadata was insufficient. The emitted `identity.sign_in.anomaly_observed` event contains only the baseline label and signal names. It does not persist the current raw IP or user-agent in the anomaly payload.

## Safety boundary

- Detection is advisory and never blocks sign-in, revokes sessions, locks accounts, or triggers a challenge.
- A missing or failed anomaly baseline does not block a valid sign-in. The service logs an internal error without copying client metadata into that log record.
- The baseline is limited to sessions that are active under existing absolute- and idle-expiry rules. It is not a geo-location, impossible-travel, device-attestation, or long-term behavioral model.
- No score thresholds, automated response, alerting destination or new retention policy is inferred.

## Verification

Pure detector tests cover same-device, new-IP, new-user-agent, no-baseline, insufficient-metadata and non-disclosure behavior. Identity-service tests verify that changed active-session fingerprints create a value-safe anomaly event while sign-in proceeds.

## Acceptance still required

The exact owner-supplied CO-012 acceptance wording is absent. Automated challenge/alert actions, scoring thresholds, historical retention, geolocation and broader risk response remain unimplemented and require verified requirements plus owner approval where they change account access or personal-data retention.
