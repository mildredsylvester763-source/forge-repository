# TQ-007: AI step recording

## Behaviour

- Recording a step runs one fixed pipeline: capability check (owner or active participant with the steps capability), acting check (the session must be running or manual), safe mode evaluation FIRST, the platform vocabulary second, narration third. Security before mechanics.
- A recorded step gets the next sequence number, an actor, the raw action and target, the narration, and a payload (value, direction, key, count, extra). The payload is stored but never echoed: narration reports typed values by length only.
- Refusals are named: session-not-found:x, collaboration-capability-denied:role:steps, session-not-acting:status, safe-mode-action-missing, safe-mode-blocks-*, platform-action-unknown:x, platform-action-unsupported:a:p, narration-missing-target:action.

## Where it lives

src/modules/live-testing/live-testing-service.ts (recordStep) over engine/safe-mode.ts, engine/platform-capability.ts and engine/step-narration.ts; POST /v1/live-testing/sessions/steps.

## Limits, stated plainly

Steps are recorded sequentially: the sequence number is the count plus one. There is no concurrent-step merge.
