# CO-004: Enterprise SSO

**Implementation status:** partial, provider-neutral SAML 2.0 service-provider engine and persistent replay-cache adapters. No customer IdP has been connected; no production enterprise SSO sign-in is claimed.

## Implemented backend foundation

- Adds `@node-saml/node-saml` 5.2.0 as the SAML 2.0 service-provider protocol engine. FORGE owns configuration, provider scoping, HTTP integration seams, persistence, identity mapping and session issuance.
- Validates provider identifiers, production HTTPS endpoints, exact IdP issuer, certificate presence/size, paired SP signing key/certificate configuration, RelayState size and bounded assertion/request lifetimes.
- Creates SP-initiated AuthnRequests and generates SP metadata for customer IdP registration.
- Requires signed SAML Responses and signed Assertions, exact configured audience and IdP issuer, `InResponseTo` validation in `always` mode, replayed-assertion rejection, bounded assertion age and strict clock-skew configuration.
- Rejects unsolicited/IdP-initiated responses because only SP-initiated request IDs are accepted.
- Requires an injected SAML cache with atomic `consumeAsync` and `saveIfAbsentAsync` operations. Cache keys are namespaced per customer IdP.
- Implements bounded, atomic SQLite and PostgreSQL cache adapters for SAML request IDs and replayed assertion IDs. The development/test in-memory adapter is also available.
- SP AuthnRequest signing is configurable; when enabled, a private key and matching public certificate are both required and SHA-256 signing/digest algorithms are selected explicitly.

## Deliberate non-implementation boundary

- No customer-specific IdP metadata, signing certificate, SSO endpoint or production callback domain is fabricated.
- No HTTP callback route is mounted in the application yet. The service-provider engine exposes login-start, response-validation and metadata operations for later integration.
- No SAML NameID/attribute-to-FORGE-user mapping, tenant provisioning, account linking, auto-provisioning, role/group mapping or FORGE session issuance is implemented. Those semantics must be agreed before a verified SAML profile becomes a FORGE account session.
- The SQLite cache is single-database/single-server. The PostgreSQL adapter is implemented but has not yet passed a real PostgreSQL integration run. A shared cache must be used by every instance that serves the same customer IdP.
- Single Logout (SLO), encrypted assertions, metadata auto-import and certificate rollover orchestration are not claimed as implemented.
