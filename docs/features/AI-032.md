# AI-032: Failure-case mining

## Behaviour

- Failed cases are mined into a named batch: content is fingerprinted (casefp prefix), exact duplicates are dropped and counted, and survivors rank by weight then id.
- An empty failure set is refused (mining-no-failures); a batch over the cap is refused loudly (mining-cap-exceeded), never trimmed.
- Duplicate batch ids are a 409 conflict; refusals named: mining-no-cases, mining-invalid-cap, mining-case-no-id, mining-duplicate-case, mining-case-no-content, mining-case-invalid-passed, mining-case-invalid-weight.

## Where it lives

src/modules/ai-training/engine/product-experiment-engine.ts (pure), reached through POST /v1/ai-training/mining/batches.

## Limits, stated plainly

Dedupe is exact content, not near-duplicate, so near misses both survive. Weight is declared by the caller, not learned.
