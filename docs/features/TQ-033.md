# TQ-033: E2E suites from recorded sessions

## Behaviour

- A recorded session (up to 200 steps over navigate, click, type, wait, assert) is replayed into an e2e suite: consecutive duplicate steps collapse into one with a deduped count, assert steps become explicit assertions named assert:target, and checkpoint flags on non-assert steps become checkpoint:after:action:stepNumber assertions anchored to the deduped step number.
- The checkpoint flag is taken from the first occurrence of each deduped step; collapsed duplicates are ignored. Steps always carry action, target and value.
- Malformed input is refused by name: e2e-session-name-missing, e2e-session-name-too-long, e2e-steps-empty, e2e-steps-limit:n, e2e-step-action-missing, e2e-action-unknown:x.

## Where it lives

src/modules/test-generation/engine/e2e-session-replay.ts (pure), reached through POST /v1/test-generation/e2e/plan. GET /v1/test-generation/e2e/actions lists the catalog.

## Limits, stated plainly

The suite replays what was recorded: it cannot invent coverage for screens nobody visited, and dedupe only collapses exact consecutive repeats.
