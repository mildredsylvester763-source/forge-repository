# AI-083: Parallel agent conflict detection

## Behaviour

- Agents declare the resources they read and write. Reads and writes are optional and default to empty.
- Strict mode (the default) flags write-write and read-write hazards; relaxed mode flags write-write only.
- In a read-write conflict the writer is always named first, so verdicts are unambiguous.
- Conflicts are deduplicated per pair and resource, then sorted deterministically by writer, reader, resource and kind.
- Malformed input is refused by name: parallel-agents-empty, parallel-agent-missing:1, parallel-agent-id-duplicate:a, parallel-reads-invalid:a, parallel-mode-unknown:loose.

## Where it lives

src/modules/task-runtime/engine/parallel-agents.ts (pure), reached through POST /v1/tasks/parallel/conflicts and GET /v1/tasks/parallel/modes.

## Limits, stated plainly

Detection is a pure pre-flight check: it answers whether a plan is safe to run in parallel, it does not schedule or lock anything.
