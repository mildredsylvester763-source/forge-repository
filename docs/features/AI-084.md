# AI-084 - Long-running tasks with checkpoints and resume

Catalog row (Part 01 With Plans): "Long-running tasks with checkpoints and resume" - Plan from: Pro, Engine: General, no pass needed. Base plan gate; Pro or above.

## What it is
A long-running task starts, records checkpoints (a step plus a state bundle), pauses, resumes from a chosen checkpoint or the latest one, and completes. Every state change is refused by name when the status does not allow it. Pure, deterministic.

## Engine
`src/modules/ai-training/engine/longrunning-task-engine.ts` - pure.
- `startLongRunningTask({ taskId, kind })` - a non-empty id and kind; the task starts `running` with no checkpoints.
- `recordCheckpoint(task, { step, state })` - only while running; the step is a non-negative integer and the state a non-empty object. Checkpoint ids are `ltc_<taskId>_<n>`. Returns the new task record; the caller record is never mutated.
- `pauseLongRunningTask(task)` / `completeLongRunningTask(task)` - only while running.
- `resumeLongRunningTask(task, fromCheckpointId?)` - only while paused; a given checkpoint id must exist; with none given the latest checkpoint is chosen (or nothing, for a task with no checkpoints). `resumedFrom` always tells the truth.

Refusals: `task-start-no-id`, `task-start-no-kind`, `task-not-running:<status>`, `task-not-paused:<status>`, `checkpoint-bad-step`, `checkpoint-no-state`, `checkpoint-unknown:<id>`.

## Routes (all POST, session required, gate: pro)
- `/v1/ai-training/tasks/start` - 201, the task and its createdAt (409 longrunning-task-duplicate)
- `/v1/ai-training/tasks/checkpoint` - 200, the checkpoint and the task
- `/v1/ai-training/tasks/pause` / `/resume` / `/complete` - 200, the task
- `/v1/ai-training/tasks/status` - 200, the task and its createdAt (404 longrunning-task-not-found)

## Honest state
Tasks live in an in-memory session Map (the streaming-sessions precedent): a restart clears them, nothing is persisted yet. The checkpoint state bundle is stored as given; the engine never invents progress.
