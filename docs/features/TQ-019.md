# TQ-019: Human session vs AI session comparison

## Behaviour

- POST /v1/live-testing/sessions/compare takes the owner's finished live testing session as the AI run and the recorded human run, and returns one verdict: humanSteps, aiSteps, stepDelta, humanDurationMs, aiDurationMs, durationDeltaMs, faster, sameOutcome and a one line summary.
- The AI side is measured from the session itself: recorded step count, startedAt to endedAt duration, and the session outcome. The human side supplies steps, durationMs and an outcome of completed, failed or cancelled.
- Only the session owner can compare. Only terminal sessions can be compared; an open session is refused as comparison-session-open:STATUS.
- Broken inputs are refused by name: comparison-not-object, comparison-human-missing, comparison-ai-missing, comparison-steps-invalid:SIDE:RAW, comparison-duration-invalid:SIDE, comparison-outcome-unknown:SIDE:RAW.

## Where it lives

src/modules/live-testing/engine/session-comparison.ts (pure) through src/modules/live-testing/service.ts into src/modules/live-testing/routes.ts, POST /v1/live-testing/sessions/compare.

## Limits, stated plainly

The comparison is metric level: step counts, durations and outcomes. There is no step by step diff showing where the human and the AI diverged, and no scoring of step quality. The human run is entered by hand, so it is only as honest as the numbers the owner types in.
