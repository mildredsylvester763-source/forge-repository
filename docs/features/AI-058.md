# AI-058: Page fetch with clean extraction

## Behaviour

- Callers supply the url and html; the engine strips scripts, styles, noscript, navigation, header, footer, aside and form blocks plus html comments, then decodes a small set of entities.
- The title comes from the head title tag, capped at 500 characters. A publish date is read from a time element datetime attribute or an article:published_time or date meta tag.
- The remaining text is trimmed, capped at 200000 characters, and counted exactly by word.
- Refusals are named: extract-empty-html, extract-no-readable-text (fewer than 10 words). The service adds fetch-page-html-too-long above 300000 characters and per-workspace domain checks before extraction.
- Fetching the same url again reuses the stored page instead of re-extracting.

## Where it lives

src/modules/web-search/engine/page-extraction.ts (pure), reached through POST /v1/web-search/pages, GET /v1/web-search/pages and POST /v1/web-search/pages/list.

## Limits, stated plainly

Extraction is heuristic tag stripping, not a full html parser; malformed markup can leak fragments into the text. The kernel caps request bodies at 16 KiB, so html larger than the service limit can only arrive from internal callers; the refusal is still enforced. Only a handful of entities are decoded.
