# TQ-020: Device profile normalization

## Behaviour

- A device plus a network choice normalizes into one full profile: device, network, platform, lowEnd, cpuThrottle, offline, downlinkKbps and latencyMs.
- Names are trimmed and lowercased before matching, so "  Pixel-5  " resolves to pixel-5.
- Refusals are named and ordered: deviceprofile-not-object, device-missing, device-unknown:X, network-missing, network-unknown:X.
- Sessions created with a device carry the normalized profile, and cross-device handoff replaces it with the full catalog spec of the target device.

## Where it lives

src/modules/live-testing/engine/device-profile.ts (pure), applied when a session is created and used by POST /v1/live-testing/sessions/handoff.

## Limits, stated plainly

The profile describes simulation knobs (throttle, offline, bandwidth), not real hardware telemetry. It never changes the session status on its own.
