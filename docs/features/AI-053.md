# AI-053: Prompt and response logging with redaction

## Behaviour

- Before storage, secrets are redacted by pattern (secret keys, tokens, emails, phone numbers) and counted per kind in findings; the stored text is the redacted text, and the raw key can never survive into a stored or listed log.
- Duplicate entries are idempotent (duplicate: true, nothing stored twice). Empty entries are refused (log-empty-entry).
- The per-provider log cap is hard: the entry over the cap is refused loudly (log-over-cap), never trimmed. Logs list newest first and always tell the whole count.

## Where it lives

src/modules/ai-training/engine/model-gateway-ops-engine.ts (pure), reached through POST /v1/ai-training/gateway/logs and /v1/ai-training/gateway/logs/list.

## Limits, stated plainly

- Redaction is pattern-based. A secret in an unusual shape can slip through; the patterns are the first line, not a promise.
