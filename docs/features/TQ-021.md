# TQ-021: Low-end device and slow-network profiles

## Behaviour

- low-end-android and low-end-iphone model low-RAM hardware: lowEnd true and cpuThrottle 4, so the session behaves as if the CPU were four times slower.
- Six pinned networks cover the honest range a live app meets: offline (0 kbps, 0 ms, flagged offline), slow-2g (50 kbps, 2000 ms), slow-3g (400 kbps, 2000 ms), fast-3g (1500 kbps, 150 ms), 4g (9000 kbps, 100 ms) and wifi (30000 kbps, 40 ms).
- normalizeDeviceProfile turns a device plus a network into one full profile: device, network, platform, lowEnd, cpuThrottle, offline, downlinkKbps and latencyMs. Names are trimmed and lowercased first.
- Refusals are named and ordered: deviceprofile-not-object, device-missing, device-unknown:X, network-missing, network-unknown:X.

## Where it lives

src/modules/live-testing/engine/device-profile.ts (pure), served by GET /v1/live-testing/devices and consumed by session creation and POST /v1/live-testing/sessions/handoff.

## Limits, stated plainly

The profile describes simulation knobs, not real hardware telemetry. CPU throttle is a number the service can reason about; nothing is actually slowed down. There is no packet-level shaping, jitter or packet loss modeling.
