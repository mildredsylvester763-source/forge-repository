# TQ-021: Network condition profiles

## Behaviour

- Six pinned network conditions cover the honest range a live app meets: offline, slow-2g, slow-3g, fast-3g, 4g and wifi, each with a fixed downlink in kbps and latency in ms.
- offline is a first class condition with the offline flag set, so interruption and profile logic can treat "no network" as a planned case, not an error.
- The same six names are the only accepted network values in device profile normalization.

## Where it lives

src/modules/live-testing/engine/device-profile.ts (pure), served inside GET /v1/live-testing/devices and consumed by profile normalization.

## Limits, stated plainly

Bandwidth and latency are constants for simulation; there is no packet-level shaping, jitter or packet loss modeling.
