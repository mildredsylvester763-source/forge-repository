# AI-010: Code and data contributions

## Behaviour

- Every contribution registers with a kind from the fixed vocabulary: diff, fix, review, test, deploy. Unknown kinds are refused by name.
- A fix must reference the failing test that proves the bug (codedata-fix-no-test otherwise), and that failing test is part of the fix's identity.
- A parent must already exist, so chains are always well formed; an unknown parent is refused by name.
- Duplicate identity is the fingerprint over kind:contentHash:author:parent:failingTestId. A duplicate registration is idempotent: the existing record returns with duplicate true and nothing is appended.
- Only deploys carry a state, born pending. The transition table is pinned: pending moves to running, aborted or failed; running moves to succeeded, failed, rolled-back or aborted. All four of those are terminal and refuse every further move.

## Where it lives

src/modules/training-data/engine/codedata-engine.ts (pure), reached through POST /v1/training-data/codedata/register, POST /v1/training-data/codedata/deploy and POST /v1/training-data/codedata/list.

## Limits, stated plainly

The registry records what authors declare; it does not verify the content hash against an artifact. A refused transition changes nothing and emits nothing. A deploy that never reaches a terminal state stays where it is forever: nothing times a pending deploy out automatically.
