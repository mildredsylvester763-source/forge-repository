# TQ-029: Test data lifecycle

## Behaviour

- Test accounts derive deterministically from the session seed: the seed is normalized to a slug, usernames follow forge-slug-N, emails use the fixed fixture domain, roles cycle shopper, editor, viewer and admin, and passwords are 12 characters (5 lower, 4 upper, 3 digits, ambiguous characters excluded) generated without randomness.
- Counts run 1 to 12 with 3 as the default; invalid counts are refused as data-count-invalid:X, and seeding a seeded session refuses with data-already-seeded:N before count validation.
- Cleanup only runs on terminal sessions (completed, failed, cancelled). It marks every seeded account cleaned with a timestamp and reports a fixed four step plan: disable fixtures, purge seeded uploads, restore app settings, remove test accounts.
- Cleanup is idempotent: a session with nothing pending answers alreadyClean with an empty plan.

## Where it lives

src/modules/live-testing/engine/test-data-lifecycle.ts (pure), POST /v1/live-testing/sessions/data/seed, /data/cleanup (owner only) and /data/accounts, backed by the live_testing_accounts table.

## Limits, stated plainly

Accounts are simulated fixtures in the database; they are not real users and cannot sign in. Cleanup updates fixture state, it does not drop rows or touch external systems.
