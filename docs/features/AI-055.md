# AI-055: Capability registry: what each model can do (code, vision, audio, tools)

## Behaviour

- Each model declares capabilities from a fixed known list; unknown words are refused (capability-unknown). Capabilities are stored sorted and fingerprinted (cap_ prefix).
- Matching finds the cheapest model that supports every required capability. None is refused by name (capability-no-model-supports for a real gap, capability-no-models when the user has no models at all).

## Where it lives

src/modules/ai-training/engine/model-gateway-ops-engine.ts (pure), reached through POST /v1/ai-training/gateway/capabilities and /v1/ai-training/gateway/capabilities/match.

## Limits, stated plainly

- Capabilities are declared by whoever registers the model, not tested. A claimed capability is a claim until a request proves it.
