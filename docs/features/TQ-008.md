# TQ-008: Step narration

## Behaviour

- Every recorded action gets one human-readable narration: Clicking x, Typing n characters into x, Scrolling dir n time(s) on x, Dragging x, Hovering over x, Pressing key, Uploading a file to x, Opening x, Waiting for x, Checking x, Swiping dir, Long-pressing x, Pinching, Pressing back, Installing the app build and the rest of the fixed phrase set.
- Actions that make no sense without a target (click, tap, type, scroll, drag, hover, wait, assert, upload, menu, long-press) are refused with narration-missing-target:action. Unknown actions are refused with narration-unknown-action:x, a missing action with narration-action-missing.
- Typed values are narrated by length only. Secrets never survive into the narration by construction.

## Where it lives

src/modules/live-testing/engine/step-narration.ts (pure), used by the step recording pipeline in the service.

## Limits, stated plainly

Narration is a fixed phrase set per action, not prose generation. It never invents details the step did not carry.
