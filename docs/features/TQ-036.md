# TQ-036: Mutation testing

## Behaviour

- A mutation run plans one mutant at a time over concrete source lines using six operators: flip-boolean, arith-swap, comparison-shift, number-zero, string-empty, logical-swap. One mutant per line per operator; a mutant that reproduces the original line is skipped.
- Scoring lands every mutant in exactly one state (killed, survived, timeout); the mutation score is detected mutants as a percentage of total, against a breach threshold (default 80).
- Malformed input is refused by name: mutation-source-empty, mutation-source-limit:n, mutation-line-missing:n, mutation-operators-invalid, mutation-operator-unknown:x, mutation-mutant-limit:n, mutation-mutants-empty, mutation-mutant-id-missing, mutation-results-invalid, mutation-mutant-unknown:x, mutation-result-missing:x, mutation-state-invalid:x:id, mutation-threshold-invalid:x.

## Where it lives

src/modules/test-quality/engine/mutation-testing.ts (pure), reached through POST /v1/test-quality/mutation/plan and POST /v1/test-quality/mutation/score. GET /v1/test-quality/mutation/operators lists the catalog.

## Limits, stated plainly

Token-level operators mutate simple expressions, not arbitrary syntax trees. A line the operators cannot see is not mutated; the score measures what the operators can reach.
